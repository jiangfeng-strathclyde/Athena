# 技能演化管理

## 触发场景

- 项目复盘后出现可重复使用的方法。
- 用户多次给出稳定偏好或约束。
- 资料阅读后发现可迁移流程。
- 现有技能之间出现重复、冲突或过时。
- 某个技能执行效果不好，需要优化。

## 输入

- 原始经验：项目记录、工单、对话、代码阅读、文档摘要。
- 目标任务类型：销售、研发、科研、交付、风控、数据、硬件。
- 已有技能列表。
- 质量反馈：失败原因、返工点、用户偏好、验收问题。

## 输出

- `discard`：经验太偶然，不沉淀。
- `create`：创建新技能。
- `improve`：更新已有技能。
- `merge`：合并重复技能。
- `version_note`：技能版本更新说明。
- `quality_gate`：后续使用该技能的验收门禁。

## 工作流

1. 判断经验是否具有重复价值，避免把一次性聊天变成噪声技能。
2. 检索已有技能，查找相似职责和触发场景。
3. 如果只是补充约束，优先更新已有技能。
4. 如果职责边界不同，创建新技能。
5. 如果多个技能重复，提出合并方案。
6. 写明输入、输出、禁区、人工审批点和验收标准。
7. 由韩验进行技能质量评审，由温知登记到知识库。

## 质量门禁

- 技能必须有清晰触发条件，不能泛泛而谈。
- 技能必须产生可归档交付物。
- 技能不能扩大权限边界。
- 技能更新必须保留版本说明。
- 涉及报价、合同、付款、真实客户数据和生产系统的技能必须转人工审批。
